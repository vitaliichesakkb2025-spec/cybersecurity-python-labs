# Показ лабораторної роботи №2 у PyCharm

[← ЛР №2](README.md) · [← Головна сторінка](../../README.md)

**Python:** 3.10 або новіший · **Варіант:** 12

## Перед заняттям

1. Відкрийте в PyCharm саме папку **cybersecurity-python-labs** (корінь репозиторію), а не тільки `labs/lab02` чи стару папку `Lab2`.
2. Перевірте, що інтерпретатор налаштований на Python 3.10+ і встановлено `ruff`.
3. У терміналі PyCharm виконайте `git pull origin master`; перед захистом також можна завчасно відкрити проєкт офлайн.

## Що показати викладачу

У вбудованому терміналі PyCharm з **кореня репозиторію** послідовно запустіть:

```powershell
python -m labs.lab02.main demo
python -m labs.lab02.main analyze
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

- **`demo`:** правильний і неправильний вхід, валідація `email`, дозволи адміністратора, таймаут 900 с, вихід і записи `AuditLog`.
- **`analyze`:** зчитування 6 навчальних листів; LOW для 001/003/005 і CRITICAL для 002/004/006; створення CSV.
- **CSV:** у дереві PyCharm відкрийте `labs/lab02/data/phishing_report.csv`, покажіть `risk_score`, `risk_level`, `findings`.
- **Тести:** перевірте `Ran 27 tests` та `OK` (тести обох лабораторних).
- **Ruff:** переконайтеся в `All checks passed!` і в повідомленні про відформатовані файли.

Якщо запускаєте через зелену кнопку **Run**, у меню **Run → Edit Configurations → + → Python** вкажіть **Module name:** `labs.lab02.main`, **Parameters:** `demo` або `analyze`, **Working directory:** корінь репозиторію. Для другого завдання зручніше створити окрему конфігурацію. Простий запуск файлу `main.py` без параметра поверне помилку `argparse` — це очікувана поведінка, а не поломка.

## Типові питання

**Чому `Admin` успадковує `User`?** Адміністратор **є** користувачем (відношення IS-A). **Чому `UserAccount` містить `User` і `Session`?** Обліковий запис **має** ці об'єкти (HAS-A), тому використано композицію.

**Навіщо `@property`?** Для перевірки адреси під час присвоєння `user.email`. **Навіщо `__password_hash`?** Подвійне підкреслення викликає name mangling і зменшує ризик випадкового доступу; це не криптографічний захист.

**Як перевіряється пароль?** За допомогою `hashlib.pbkdf2_hmac` з випадковою сіллю та порівнянням `hmac.compare_digest`. **Що перевіряє таймаут?** Сесія вважається активною протягом 900 секунд від останньої активності (UTC).

**Чому позначки CRITICAL?** Різні домени `From` та `Return-Path` або `Reply-To`, підозрілі слова в `Subject` та/або багато `Received`. Це **евристика**, а не доказ шахрайства.

**Навіщо `logging`?** Щоб розрізняти `DEBUG`, `INFO`, `WARNING`, `ERROR` та фільтрувати події. **Навіщо `argparse`?** Для керування параметрами й зрозумілих помилок введення.

**Як демонструвати власний варіант?** Покажіть оригінальні навчальні файли в `data/data_v12/`, виконання `analyze`, CSV та алгоритм у `task2.py`.

Документація коду й коментарі у ЛР №2 українською, а Python-ідентифікатори та стандартні імена полів залишено без змін. Дані в `data_v12` — файли з навчального архіву.
